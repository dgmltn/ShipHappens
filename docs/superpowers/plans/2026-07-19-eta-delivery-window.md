# ETA Delivery Window Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the single-valued `etaTime` with a carrier-agnostic `etaWindowStart`/`etaWindowEnd` pair across domain, persistence, and UI, so the app can hold and render a delivery window like "3:00 – 5:00 PM".

**Architecture:** A lone cutoff becomes an open-ended window (`start = null`, `end = cutoff`) so existing UPS/USPS behavior ("by 2:30 PM") is preserved bit-for-bit. Task 1 adds a pure formatter with no dependencies. Task 2 performs the model/persistence/source rename as one behavior-preserving commit (a rename cannot be split without a red build) plus the Room auto-migration. Task 3 switches the UI to the new formatter, which is the only behavior change.

**Tech Stack:** Kotlin Multiplatform (Kotlin 2.4, Gradle 9.6), Room 3 (`androidx.room3`) with KSP + exported schemas, kotlinx-datetime `LocalTime`, Compose Multiplatform, kotlin.test.

## Global Constraints

- **No new scraper/parser window parsing.** `AmazonWebSpec.kt`, `UspsWebSpec.kt`, and `UpsWebSpec.kt` JS blobs are NOT modified in this plan. Amazon continues to yield date-only.
- **Window semantics:** `start = null, end = X` → `by X`. `start = X, end = Y` → `X – Y`. Both null → omitted.
- **Range format:** collapse the meridiem when start and end share it (`3:00 – 5:00 PM`); show both when they differ (`11:30 AM – 1:30 PM`). Uppercase `AM`/`PM`, separator is a spaced **en-dash** `" – "` (U+2013), matching the existing "by 8:00 PM" styling.
- **Migration is non-destructive:** Room auto-migration, version 1 → 2, `@RenameColumn` carrying `etaTime` → `etaWindowEnd`. Parcel data (name, tracking #, events, status) must survive, and so must each existing cutoff value. *(Amended after final review — originally `@DeleteColumn`, which discarded recoverable ETA times.)*
- **Commit message prefix:** every commit starts with a one-word module tag in square brackets, e.g. `[ui]`, `[data]`, `[domain]`.
- **Never run `git add -A`** — a stray `gradle/gradle-daemon-jvm.properties` is auto-generated by some Gradle invocations in this repo and must not be committed. Stage explicit paths only.

```kotlin
package com.shiphappens.ui.util

import kotlinx.datetime.LocalDate
import kotlinx.datetime.LocalTime
import kotlinx.datetime.isoDayNumber
import kotlinx.datetime.number

private val WD = listOf("Mon", "Tue", "Wed", "Thu", "Fri", "Sat", "Sun")
private val MO = listOf("Jan", "Feb", "Mar", "Apr", "May", "Jun", "Jul", "Aug", "Sep", "Oct", "Nov", "Dec")

// kotlinx-datetime 0.8.0: monthNumber/dayOfMonth are deprecated in favor of month.number/day.
fun LocalDate.designFormat(): String = "${WD[dayOfWeek.isoDayNumber - 1]}, ${MO[month.number - 1]} $day"

private fun LocalTime.clock12(): String {
    val h12 = when { hour == 0 -> 12; hour > 12 -> hour - 12; else -> hour }
    return "$h12:${minute.toString().padStart(2, '0')}"
}

private fun LocalTime.meridiem(): String = if (hour < 12) "AM" else "PM"

fun LocalTime.design12h(): String = "${clock12()} ${meridiem()}"

/**
 * Renders an ETA delivery window.
 *
 * - both set   -> "3:00 – 5:00 PM" (meridiem collapsed when shared, else "11:30 AM – 1:30 PM")
 * - end only   -> "by 8:00 PM"
 * - no end     -> null (a start without an end is degenerate; no carrier produces it)
 */
fun formatEtaWindow(start: LocalTime?, end: LocalTime?): String? {
    if (end == null) return null
    if (start == null) return "by ${end.design12h()}"
    val startText = if (start.meridiem() == end.meridiem()) start.clock12() else start.design12h()
    return "$startText – ${end.design12h()}"
}
```

## Post-implementation amendments (final whole-branch review)

Two Important findings were accepted and applied in commit `279b229`, after all three tasks had
passed their task-scoped reviews. Both changed decisions this plan had originally mandated:

1. **`@DeleteColumn` → `@RenameColumn`** in `ShipHappensDb.kt`. The old `etaTime` value is already
   semantically a window *end*, so deleting it discarded recoverable data — existing parcels would
   have degraded from "Sat, Jul 11 · by 9:00 PM" to "Sat, Jul 11" until their next refresh, and
   manual-refresh users would never have recovered it. The exported `2.json` is unchanged (the
   final schema is identical either way); only the generated migration SQL differs.
2. **Atomic window merge** in `ParcelRepository.applySnapshot`. Task 2 Step 3 specified independent
   per-field preserve-on-null for the two bounds; that lets a stale start attach to a newer end and
   render a window no carrier quoted. The window is now merged as one value, covered by a new
   regression test in `ApplySnapshotTest`.

  `etaWindowEnd` from the JS; every other layer is already in place.
- Any change to the list/home card, which still shows a whole-day countdown ring.
- Any new UI affordance beyond the existing single-line "Estimated delivery" text.
